# Architecture

Three Scaleway instances become one kubeadm cluster. The master also carries the ingress
controller, a HAProxy front and the public IP that MetalLB advertises; the nodes host the
workloads, GitLab among them. Everything is reached through `*.todevops.local`, resolved by
`/etc/hosts` entries on the VMs and on your machine.

## Layout

```
plans/
  scaleway.tf                 provider scaleway (fr-par-1), 3 x DEV1-L ubuntu_jammy, one public IP each, outputs
  terraform_values.json       terraform output -json (ignored by git)
terraform_to_ansible_values.sh  writes the output IPs and names into inventories/scaleway.ini
inventories/scaleway.ini      master (vm3), node1 (vm1), node2 (vm2); groups k8s-master, k8s-nodes, k8s
vars/scaleway.yml             domain, sub-domains, passwords, GitLab admins, repository to import
ansible.cfg                   roles_path ./roles, no host key checking, pipelining
set_local_hosts.yml           role setup_domain_names on localhost
playbooks/
  infrastructure.yml          tags base, k8s-setup, k8s-gitlab, k8s-linkerd, k8s-logging, k8s-argocd
  setup-continuous-deployment.yml   tags import-repository, configure-argocd-repository
roles/
  setup_domain_names          /etc/hosts block: VM names, registry, gitlab, kibana, linkerd, argocd -> master IP
  install_kubernetes_utils    Docker 19.03, kubectl 1.22.11, Helm 3
  setup_kubernetes_cp         kubeadm init, Flannel, ingress-nginx, MetalLB, OpenEBS, dashboard, metrics, certs, HAProxy
  setup_kubernetes_node       kubeadm join with the join-command fetched from the master
  deploy_gitlab               GitLab CE Helm chart 6.2.2, admin users
  bind_docker_registry        docker login on the registry, regcred secret in the default namespace
  install_kubernetes_linkerd  Linkerd CLI and control plane, linkerd-viz chart, basic-auth ingress
  install_kubernetes_logging  kube-logging chart (Elasticsearch, Fluentd, Kibana) from files/charts
  install_kubernetes_argocd   Argo CD 2.4.8 manifests, admin password patch, SSL passthrough ingress
  setup_gitlab_ssh_key        master SSH key registered on the GitLab user
  setup_gitlab_repository     clone the public repository, push it to a new GitLab project
  configure_argocd_repository argocd CLI login, repository credentials, Application manifest
join-command, config          generated by k8s-setup, ignored by git
```

## Machines

| Inventory host | Terraform resource | Size | Role |
|----------------|--------------------|------|------|
| `master` (machine_name `vm3`) | `todevops-k8s-master`, 80 GB root volume | DEV1-L | control plane, ingress, MetalLB IP, HAProxy, certificates |
| `node1` (`vm1`) | `todevops-k8s-node-1`, 40 GB | DEV1-L | worker (GitLab and its registry end up here or on node2) |
| `node2` (`vm2`) | `todevops-k8s-node-2`, 40 GB | DEV1-L | worker |

The master taint is removed, so workloads can also land on it. Ansible connects as `root`.

## Network path

```
  Browser           *.todevops.local -> master public IP (set_local_hosts.yml)
     |
  HAProxy           on the master, apt package; 80 -> NodePort 31111, 443 (ssl, todevops.local.pem) -> 31112
     |
  ingress-nginx     Service of type LoadBalancer patched to NodePorts 31111/31112/31100 (GitLab SSH)
     |              MetalLB answers for the master IP; class nginx
     |
  Ingress rules     gitlab.* (chart), linkerd.* (basic auth), kibana.*, argocd.* (SSL passthrough)
     |
  Services          GitLab, linkerd-viz web :8084, Kibana :5601, argocd-server :443, my-app
```

The wildcard certificate is generated on the master by `generate-wildcard-certificate.sh`
(`todevops.local.crt`, `.key`, `.pem`), stored as the `gitlab-wildcard-tls` secret and trusted
by the Argo CD CLI with `argocd cert add-tls`. It is self-signed: browsers warn, Docker on the
VMs is configured with `insecure-registries` for `registry.todevops.local`.

## Continuous deployment

1. `setup_gitlab_ssh_key`: waits for GitLab, creates an RSA key on the master if needed and adds
   it to the GitLab user through the API.
2. `setup_gitlab_repository`: creates the project `internal_repository_name`, clones
   `public_repository_to_clone`, drops its `.git`, re-initialises on `main` and pushes over SSH
   on port 2222.
3. `configure_argocd_repository`: installs the `argocd` CLI, logs in, trusts the GitLab
   certificate, then applies a `repo-secret`, the `argocd-cm` repositories entry, a hostAliases
   patch on `argocd-repo-server` (gitlab domain to master IP) and an `Application` named
   `myapp-argo-application` that syncs `manifests/` of the repository into `my-app` with
   `selfHeal` and `prune`.

The default repository is [Nginx-Template-Deployment](https://github.com/verovec/Nginx-Template-Deployment):
three replicas of nginx and a Service.

## Variables

`vars/scaleway.yml`, passed with `--extra-vars @vars/scaleway.yml`:

| Variable | Default | Used by |
|----------|---------|---------|
| `domain` | `todevops.local` | every sub-domain below, certificates, `/etc/hosts` |
| `registry_domain`, `registry_login_domain` | `registry.<domain>`, `https://...` | Docker insecure registry, `bind_docker_registry` |
| `linkerd_domain`, `kibana_domain`, `argocd_domain` | `<service>.<domain>` | ingress rules and `/etc/hosts` |
| `linkerd_viz_user`, `linkerd_viz_password` | `admin` / `admin` | basic auth of the Linkerd dashboard |
| `argocd_default_password` | `mySuperSecurePassword` | patched into `argocd-secret` |
| `gitlab_domain`, `gitlab_external_url`, `gitlab_shell_url` | `gitlab.<domain>`, `https://...`, `gitlab.todevops.local:2222` | chart values, repository push |
| `gitlab_root_password` | `mySuperSecurePassword` | initial root password secret |
| `gitlab_admins` | `flav`, `jane` | admin users created through the API |
| `public_repository_to_clone`, `internal_repository_name` | `verovec/Nginx-Template-Deployment` | repository imported and deployed |

Role-level knobs: `k8s_nodes_force_recreation` (control plane) and `k8s_nodes_force_rejoin`
(nodes), both `false`, force a `kubeadm reset` before init or join.
